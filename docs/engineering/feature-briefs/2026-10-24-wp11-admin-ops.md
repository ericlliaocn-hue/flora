## 1. 背景（一句话）

WP0–WP10 已跑通从注册登录、预付费冻结/结算、真实 Anytoken 出图、火山 TOS 存储到画布/素材/历史云同步的完整 C 端闭环；作为第一阶段收官包（WP11 / M4），本包在不引入第二套创作画布、不破坏单账本与瘦 worker 边界的前提下，提供**与 C 端路由及权限隔离的 Admin 运维与配置后台**，让运营不连数据库也能完成：**查用户与钱包流水、受控手工充值（topup）、查任务/步骤与 `provider_task` 上游原始报错、死信/失败任务一键重投、在线热改 `i18n_message` 友好文案、以及模型展示项上下架**。

### Part A：数据库迁移 `V7__create_admin_ops.sql` 与管理员角色鉴权

#### A1. 新增 Flyway 迁移 `api/src/main/resources/db/migration/V7__create_admin_ops.sql`

> **严禁修改 `V1`–`V6` 任何已有迁移文件**（否则会破坏已跑过迁移的本地库 Flyway checksum）。所有增量全部落入 `V7__create_admin_ops.sql`：

1. **`users` 表新增 `role` 列**：
   ```sql
   ALTER TABLE users
       ADD COLUMN IF NOT EXISTS role TEXT NOT NULL DEFAULT 'user'
       CHECK (role IN ('user', 'admin'));
   ```
2. **新建 `model_display_config` 表**（对齐 `docs/engineering/data-model/README.md` 的「模型展示配置 | 运营 | WP11」与 `MILESTONES.md` 的「上下架一个模型展示项」；这是展示配置表，**不是**渠道密钥或额度账本）：
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `model TEXT NOT NULL`（如 `gpt-image-2`）
   - `capability TEXT NOT NULL DEFAULT 'image.generate'`
   - `display_name TEXT NOT NULL`
   - `enabled BOOLEAN NOT NULL DEFAULT true`
   - `sort_order INT NOT NULL DEFAULT 0`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
   - 唯一约束：`CONSTRAINT model_display_config_model_key UNIQUE (model)`
   - 预置 4 条真实 Anytoken 生图模型种子（`ON CONFLICT (model) DO NOTHING`）：
     - `('gpt-image-2', 'image.generate', 'GPT Image 2', true, 10)`
     - `('gpt-image-2.5-flare', 'image.generate', 'GPT Image 2.5 Flare', true, 20)`
     - `('gpt-image-2.5-sunburst', 'image.generate', 'GPT Image 2.5 Sunburst', true, 30)`
     - `('image2', 'image.generate', 'Image 2', true, 40)`
3. **新增错误码 `FORBIDDEN` 并写入 `i18n_message` 种子**（`ON CONFLICT (key, locale) DO NOTHING`）：
   - `('FORBIDDEN', 'zh', '无权访问管理后台。')`
   - `('FORBIDDEN', 'en', 'You do not have permission to access the admin console.')`
   - `('error.FORBIDDEN', 'zh', '无权访问管理后台。')`
   - `('error.FORBIDDEN', 'en', 'You do not have permission to access the admin console.')`
   - 同步在 `ErrorCodes.java` 增加 `public static final String FORBIDDEN = "FORBIDDEN";`，在 `I18nDefaultCatalog.java` 的 `SEEDS` 中登记 `ErrorCodes.FORBIDDEN` 的中英默认词条。

#### A2. 管理员角色（`role`）与本地/配置引导（Bootstrap Admin）

1. **`User`、`CurrentUser`、`AuthSession` 扩展 `role` 字段**：
   - `User` record 增加 `String role`（从 `users.role` 读取，空时兜底 `"user"`；保留兼容构造器以免破坏旧单测）。
   - `CurrentUser(UUID userId, String username, String locale, String role)` 与 `AuthSession(UUID userId, String username, String locale, String token, String role)`：JSON 序列化后 `GET /api/v1/auth/me`、`POST /api/v1/auth/login`、`POST /api/v1/auth/register` 响应的 `data` 中包含 `"role": "user" | "admin"`（提供兼容构造器默认 `"user"` 以保证已有测试无缝编译通过）。
2. **配置项 `pilipala.admin.bootstrap-usernames`**：
   - 在 `api/src/main/resources/application.yml` 的 `pilipala:` 下增加：
     ```yaml
     admin:
       # 逗号分隔的初始管理员用户名列表：命中者在注册或登录时自动升为 admin 角色
       bootstrap-usernames: ${PILIPALA_ADMIN_BOOTSTRAP_USERNAMES:admin,pilipala_admin}
     ```
   - 在 `RegisterUser` 与 `LoginUser`（以及 `GetCurrentUser`）中：若用户名的去空白小写命中 `pilipala.admin.bootstrap-usernames` 且库里 `role != 'admin'`，自动调用 `UserRepository.updateRole(user.id(), "admin")` 并返回 `role = "admin"`。这样本地联调与自动化验收只需注册或登录 `admin`（或 `pilipala_admin`）即可直接获得管理员权限，无需手写 SQL 改库。
3. **Admin 权限守卫 `AdminGuard`**：
   - 所有 `/api/v1/admin/**` 接口必须先经过 Sa-Token 登录校验（已在 `/api/v1/**` 闸门内，未登录返回 `ok=false, error_code="UNAUTHORIZED"`），再调用 `AdminGuard.requireAdmin()`。
   - 若当前登录用户的 `role` 不是 `"admin"`，抛 `AuthException.forbidden()`，由 `AuthExceptionHandler` 返回 HTTP 200 统一信封：
     ```json
     {
       "ok": false,
       "data": null,
       "error_code": "FORBIDDEN",
       "message": "无权访问管理后台。"
     }
     ```

### Part B：`api` 后端 Admin 运维与配置接口（`art.pilipala.api.admin`）

新建包 `art.pilipala.api.admin`（按 `domain` / `infra` / `application` / `web` 分层，不造上帝类，每个用例/控制器职责单一）：

#### B1. 用户查询、手工充值（Top-Up）与钱包流水排查

1. **`GET /api/v1/admin/users?q=&limit=50`**
   - 查询参数：
     - `q`（可选）：按 `username` 模糊匹配（`ILIKE '%' || ? || '%'`），空串或未传则查全部
     - `limit`（可选，默认 `50`，收敛到 `1..200`）
   - 排序：按 `users.created_at DESC`
   - 响应 `data`：`List<AdminUserView>`，每项含：
     - `user_id`（UUID string）
     - `username`（string）
     - `role`（`"user"` | `"admin"`）
     - `locale`（string | null）
     - `available`（long，来自 `wallet.available`，若该用户尚无 `wallet` 行则为 `0`）
     - `frozen`（long，来自 `wallet.frozen`，若无 `wallet` 行则为 `0`）
     - `created_at`（ISO 8601）
     - `updated_at`（ISO 8601）
2. **`POST /api/v1/admin/wallets/{userId}/topup`**
   - 请求体：`{ "amount": 100 }`（`amount` 必须为正整数 `> 0`，否则返回 `VALIDATION_ERROR`；若 `userId` 在 `users` 表不存在，返回 `VALIDATION_ERROR`）。
   - **单账本红线**：必须直接调用现有的 `TopUpWallet.topUp(userId, amount)`（内部走 `WalletService.credit(userId, amount)`），在同一事务内增加 `wallet.available` 并写入一条 `wallet_ledger`（`type = 'topup'`, `amount = amount`）。**严禁绕过 `TopUpWallet` 直接 `UPDATE wallet`**。
   - 响应 `data`：`WalletView`（`user_id`, `available`, `frozen`, `updated_at`）。
3. **`GET /api/v1/admin/wallets/{userId}/ledger?limit=50`**
   - 查询指定用户的最近 `wallet_ledger` 流水（`limit` 默认 `50`，收敛 `1..200`，按 `created_at DESC` 排序）。
   - 响应 `data`：`List<AdminLedgerEntryView>`，每项含：
     - `id`（UUID string）
     - `user_id`（UUID string）
     - `type`（`"topup"` | `"freeze"` | `"confirm"` | `"release"`）
     - `amount`（long）
     - `hold_id`（UUID string | null）
     - `job_id`（UUID string | null）
     - `created_at`（ISO 8601）

#### B2. 任务查询、`provider_task` 原文排障与死信/失败任务重投

1. **`GET /api/v1/admin/jobs?status=&user_id=&limit=50`**
   - 查询参数：
     - `status`（可选）：过滤 `job.status`（如 `dead`、`failed`、`running`、`queued`、`succeeded`、`cancelled`），非法枚举值返回 `VALIDATION_ERROR`
     - `user_id`（可选）：按用户 UUID 过滤
     - `limit`（可选，默认 `50`，收敛到 `1..200`）
   - 排序：按 `job.created_at DESC`
   - 响应 `data`：`List<AdminJobView>`，每项含：
     - `job_id`, `user_id`, `username`（关联 `users.username`）, `status`, `capability`, `model`, `prompt`（从 `params` JSON 提取 `prompt` 字符串，缺失为空串）
     - `attempt`, `max_attempts`, `hold_id`（string | null）, `hold_status`（关联 `wallet_hold.status`：`"frozen"` | `"confirmed"` | `"released"` | `null`）
     - `error_code`（string | null）, `created_at`, `updated_at`
     - `steps`：该任务的全部 `job_step` 列表（按 `attempt ASC`），每项含 `step_id`, `attempt`, `status`, `error_code`, `provider_task_id`, `started_at`, `ended_at`
     - `provider_tasks`：该任务关联的全部 `provider_task` 列表（按 `created_at ASC`），每项含：
       - `id`（UUID string）
       - `job_step_id`（UUID string | null）
       - `upstream_request_id`（string | null）
       - `raw_status`（string | null）
       - `raw_body`（JsonNode / Object | null）
       - `created_at`（ISO 8601）
   - **安全边界（ADR 0005）**：`provider_task` 的 `raw_status` 与 `raw_body` **只允许出现在 `/api/v1/admin/jobs` 响应中**；C 端 `/api/v1/jobs/**` 严禁包含这些字段。
2. **`POST /api/v1/admin/jobs/{jobId}/retry`**
   - 用途：将处于 `dead` 或 `failed` 状态的任务重新入队执行。
   - 校验：
     - 任务不存在 → 返回 `JOB_NOT_FOUND`
     - 任务当前 `status` 不是 `dead` 且不是 `failed` → 返回 `VALIDATION_ERROR`
   - **关键状态与账本一致性细节（必须严格按此实现）**：
     1. **保留历史 `job_step` 与 `provider_task` 审计痕迹，不重置 `attempt = 0`**：因为 `job_step` 有唯一约束 `UNIQUE (job_id, attempt)`，且 `JdbcJobRepository.claim` 会执行 `attempt = attempt + 1`。重投时保持当前 `attempt` 不变，将 `max_attempts` 更新为 `GREATEST(max_attempts, attempt) + 1`，并将 `status` 设为 `'queued'`、`error_code = NULL`、`cancel_requested_at = NULL`、`updated_at = now()`。
     2. **已释放冻结单（`released` hold）防冲突处理**：当任务此前进入 `dead` 时，`HoldSettlement` 可能已将其关联的 `wallet_hold` 结算为 `'released'`。由于 `WalletService.finalize` 严禁将 `'released'` 冻结单二次转为 `'confirmed'`，重投时若检查到 `job.hold_id` 对应的 `wallet_hold.status != 'frozen'`，必须在重投更新 `job` 时将 `job.hold_id` 置为 `NULL`（表示原冻结单已退回结清，本次运维重投不再二次结算旧冻结单）；若 `wallet_hold.status == 'frozen'` 则保留 `job.hold_id`。
     3. **写入 Outbox**：在同一事务内调用 `OutboxRepository.insertPending(eventId, "job", job.id(), JobMessagePayload.of(job.id(), eventId))`，由现有 `OutboxDispatcher` 投递给 worker 执行。
   - 响应 `data`：更新后的单条 `AdminJobView`（此时 `status = "queued"`，`max_attempts` 已 +1）。

#### B3. 动态文案 `i18n_message` 在线查询与热更新

1. **`GET /api/v1/admin/i18n-messages?q=`**
   - 返回 `i18n_message` 表中的词条列表（按 `key ASC, locale ASC` 排序；若传了非空 `q`，按 `key` 或 `template` 包含 `q` 过滤）。
   - 每项 `I18nMessageView` 含：`id`, `key`, `locale`（`"zh"` | `"en"`）, `template`, `updated_at`。
2. **`PUT /api/v1/admin/i18n-messages`**
   - 请求体：`{ "key": "WALLET_INSUFFICIENT", "locale": "zh", "template": "余额不足，请联系管理员充值。" }`
   - 校验：
     - `key` 必填，去空白后长度 `1..128`
     - `locale` 必填，只能是 `"zh"` 或 `"en"`
     - `template` 必填，去空白后长度 `1..1000`
     - 不合法一律返回 `VALIDATION_ERROR`
   - 实现：调用现有的 `I18nMessageRepository.upsert(key, locale, template)`。由于 `I18nMessageService.resolve` 直接查 `I18nMessageRepository`，写入后**无需重启 `api`**，下一次触发对应错误码时即刻返回新文案。
   - 响应 `data`：更新后的 `I18nMessageView`。

#### B4. 模型展示配置 `model_display_config` 管理与读取

1. **`GET /api/v1/admin/models`**
   - 返回 `model_display_config` 全部行（按 `sort_order ASC, model ASC` 排序）。
   - 每项 `ModelDisplayConfigView` 含：`id`, `model`, `capability`, `display_name`, `enabled`, `sort_order`, `updated_at`。
2. **`PUT /api/v1/admin/models/{model}`**
   - 请求体：`{ "display_name": "GPT Image 2", "capability": "image.generate", "enabled": false, "sort_order": 10 }`（支持修改 `display_name`、`enabled`、`sort_order`、`capability`；若 `{model}` 不存在则 upsert 插入一行）。
   - 校验：`model` 与 `display_name` 非空，否则返回 `VALIDATION_ERROR`。
   - 响应 `data`：更新后的 `ModelDisplayConfigView`。
3. **`GET /api/v1/models`（C 端已登录可读）**
   - 返回 `enabled = true` 的模型展示配置列表（按 `sort_order ASC, model ASC`），供前端读取当前上架的托管生图模型列表。
